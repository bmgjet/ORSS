Every function and module: P13

The 57 modules and 13 stock functions File > New ROM > Create can build into the P13 skeleton, from the modules' own headers. The bare skeleton leaves 6,794 bytes of the 32 KB free. The modules share a library (the cut requests, the fuel and timing trims, the outputs) of about 1,047 bytes, built in once with the first module that needs it; the sizes below are what each adds on top of that, with anything it needs counted separately.

Not tested on a carThe P13 skeleton and these modules have only been run in the simulator. Simulate a P13 ROM thoroughly, and treat the first start with extra care.

The same functions on the P30 skeleton: Every function and module.

Every module starts switched off: building one in changes nothing until it is set up and enabled on its page. See Creating a custom ROM for how they are picked and checked.

Boost

Boost cut

Cuts fuel (or spark) the moment manifold pressure reaches the cut point - a lower one while the engine is cold - and lets it back in once the pressure has dropped a little under it. The safety net for a wastegate that sticks or a boost controller that runs away. Needs a MAP sensor that reads boost (a 2.5 or 3 bar sensor, with the MAP sensor scaling to match). Off until enabled.

FEAT_BOOSTCUT · 162 bytes of ROM · 1 bytes of module RAM · RAM: 1C2h-1C5h (shared cut requests), module RAM (1 byte)

Electronic boost control

Drives a boost control solenoid on PB.6 (the 82C55's spare output) at 19.5 Hz: a base duty against rpm, corrected towards a target boost against rpm (closed loop, set the gain to 0 for open loop). Below a throttle opening the solenoid is off and the wastegate holds its spring pressure. With gear detection, a cap on the duty in each gear: less boost in the low gears. Off until enabled.

FEAT_EBC · 185 bytes of ROM · 2 bytes of module RAM · RAM: module RAM (2 bytes) · cannot be built with Manual boost controller

Manual boost controller

One duty on a boost control solenoid on PB.6 (the 82C55's spare output), above an rpm and a throttle opening: the electronic version of a bleed valve, for a second boost level over the wastegate spring. Off until enabled.

FEAT_BOOSTMANUAL · 77 bytes of ROM · cannot be built with Electronic boost control

Water / methanol injection

Drives a water/methanol pump (or its solenoid) on a free output with a duty from a table against manifold pressure, as the boost controller does for its solenoid: 19.5 Hz, in 4 % steps. Only above an rpm and throttle and with the coolant warm. Off until enabled.

FEAT_WMI · 172 bytes of ROM · 3 bytes of module RAM · RAM: module RAM (3 bytes, the software PWM)

Diagnostics

Datalogging: channel stream

Logging only what you need, as fast as the line allows: the logger says which channels it wants and the ECU streams them back in frames stamped with its own 2.048 ms tick (Datalogging > Channels… picks them). Fast channels go in every frame; slow ones (temperatures, battery, codes) take turns, one a frame, so a frame stays short. Word values (rpm, injector time) are read in one go, never half old and half new. The app's own protocol, and the fastest; the HTS frame still answers alongside it. Paced by the spark calculation (datalog.asm's byte budget): it can never take the engine code's time, whatever the rpm or the line speed.

FEAT_DLSTREAM · 1,893 bytes of ROM · 18 bytes of module RAM · RAM: 3AAh-3ADh, 16 bytes of module RAM (DL_LIST) · cannot be built with Stock serial diagnostic link

Datalogging: every channel

Everything worth logging, on top of the channel stream's own list: why the fuel is cut (the rev limiter, overrun, which limiter module), the fuel map's value before the corrections and each correction after it (warm-up, intake air, baro, acceleration, tip-in, post-start, dead time, knock), each ignition correction and the knock retard, dwell, the idle target and its corrections, VTEC's state, the map indexes, the engine's flag bytes, and eight RAM addresses of your own. Pick them in Datalogging > Channels; "Everything" logs the lot (each slow one comes round in turn).

FEAT_DLEXTRA · 307 bytes of ROM · needs Datalogging: channel stream

Datalogging: HTS / ISR frame

The HTS / ISR protocol on the datalog pins at 38400 baud (the HTS wiring; 62,500 with DatalogFast): existing loggers work unchanged. 10h (or ABh) -> CDh, then 20h (or 90h) -> the 51-byte frame and its checksum, C0h+n -> byte n of it, 40h -> the HTS120 extra packet. The QD3 frame is a different protocol on the same pins: one or the other. The channel stream and the service commands go with either. Whatever is sent, the main loop's spark calculation sets how many bytes may go before the next one: fewer the higher the rpm, so logging can never take the time the engine code needs.

FEAT_DATALOG · 622 bytes of ROM · 1 bytes of module RAM · RAM: 3AAh-3ADh and 3B0h-3B7h (bank 76h), 0FDh bit 7 and module RAM (1 byte): the byte budget · cannot be built with Stock serial diagnostic link, Datalogging: QD3 frame

Datalogging: memory read

The ECU's RAM read over the datalog cable while the engine runs, 32 bytes at a time: any value or module state on the car, not just the ones a datalog channel sends (Datalogging > Codes and service… > ECU memory). The ROM itself is never sent, so the code and the maps of a tune stay in the chip.

FEAT_DLMEMREAD · 543 bytes of ROM · 1 bytes of module RAM · cannot be built with Stock serial diagnostic link

Datalogging: QD3 frame

The QD3 protocol, for scan tools and loggers that speak it: ABh -> BCh, then 46h -> a 40-byte frame (46h 26h first) and its checksum, the sum of the 40. Rpm, injector time, timing, knock retard, O2, VTEC, road speed, battery, MAP, throttle, intake air, coolant and the stored trouble codes; the other bytes hold what a QD3 ECU sends there. A different protocol from the HTS / ISR frame on the same pins: one or the other. The channel stream and the service commands go with either.

FEAT_DLQD3 · 556 bytes of ROM · 1 bytes of module RAM · cannot be built with Stock serial diagnostic link, Datalogging: HTS / ISR frame

Datalogging: serial inputs

The datalog cable works both ways: the laptop (or a small board on the ECU's datalog receive line) sends values to the ECU, and modules use them as extra inputs - a wideband the laptop reads, a switch with no spare pin for it, a flex sensor. Each value is three bytes: FFh, the input's number (00h-FDh, 254 inputs) and the value (00h-FEh); nothing comes back, and a running channel stream carries on. The ROM keeps eight, picked by number on its page. Closed loop, lean protection and flex fuel can read one as an analog input (inputs 4-11); every module with a switch input can take one as a switch (on while it is not 0). With none for a while (a cable pulled out) each reads as its default. Datalog > Channels… sends them from the log.

FEAT_DLSERIALIN · 658 bytes of ROM · 10 bytes of module RAM · RAM: module RAM (9 bytes) · cannot be built with Stock serial diagnostic link

Datalogging: service commands

Over the datalog cable (Datalogging > Codes and service…): clear the trouble codes, injectors off, the timing locked for a timing light, the maps picked, the GIO outputs forced on, and the cylinder test - one cylinder's injector cut at a time, to find the one that is not firing (cutting it changes nothing). The check-engine lamp flashes quickly while any of these is on.

FEAT_DLSERVICE · 915 bytes of ROM · 1 bytes of module RAM · RAM: 1BDh, 1C7h · cannot be built with Stock serial diagnostic link

Remote control commands

Commands over the datalog cable for a remote control panel (a phone, a dash button box): the fan on or off, the rev limit, the speed limit, the boost cut and the VTEC point set, popcorn mode (decel pops), and an anti-start lock: no password, no start. The main password runs the engine as tuned, the guest password in valet mode - a lower rev limit, a speed limit, softer timing (or, set so, no password at all means valet mode instead of no start). Also the shift light point, fuel or ignition cut for the rev limiter and launch control, the launch rpm and rolling idle. Everything set over the cable is forgotten at power-up. Off until enabled.

FEAT_REMOTE · 1,228 bytes of ROM · 21 bytes of module RAM · RAM: 0FDh bit 1, module RAM (21 bytes), and the rev cap: 2 more shared by every rev limit (lib.asm) · needs Datalogging: HTS / ISR frame · cannot be built with Stock serial diagnostic link

Trigger pattern log

The distributor's three signals as the ECU sees them, for a sensor that plays up: asked over the datalog cable, the ECU records one cam revolution - the 24 crank teeth, each one's time, and which of them the TDC and cylinder pulses came with - and sends it back (Datalogging > Trigger pattern). A missed or extra crank tooth, a TDC pulse out of place or missing, no cylinder pulse: each shows in the bars. Nothing runs until a capture is asked for, and then only for one revolution.

FEAT_TRIGLOG · 443 bytes of ROM · 28 bytes of module RAM · RAM: 0FDh bit 6 (capturing), module RAM (28 bytes) · needs Datalogging: channel stream · cannot be built with Stock serial diagnostic link

Driver aids

Shift light on the check-engine lamp

Lights the dash check-engine lamp (PC.3) above a shift rpm, one rpm for every gear or one per gear. Below it the lamp is left to whatever else drives it (the stock trouble codes, when they are built in).

FEAT_SHIFTLIGHT · 89 bytes of ROM · cannot be built with Warning lamp (coolant / battery)

Fuel

Closed loop on a wideband

Trims the fuel towards a target AFR read from a wideband O2 controller on an analog input: a target against manifold pressure, only with the engine warm and inside an rpm and throttle window, and never further than a set limit either way. Outside the window the trim goes back to nothing. Off until enabled.

FEAT_WBCL · 190 bytes of ROM · 3 bytes of module RAM · RAM: module RAM (3 bytes) · cannot be built with Stock closed-loop o2 control

Extended maps (20 load columns)

Widens the fuel, ignition and maps from 10 load columns to 20, with a 20-point load axis, for finer steps where the engine needs them. The new maps are made from the stock ones, so the engine runs exactly as before until they are changed. Every map grows by 10 bytes a row (about 1,000 bytes with the stock functions left out); the modules that switch maps use the same size.

FEAT_EXTMAPS · 988 bytes of ROM

Flex fuel

Reads the ethanol content from an ethanol sensor through an analog converter (0-5 V) on an analog input, and adds fuel and timing against it from two tables, so the car runs on anything from pump fuel to E85 without a retune. A sensor with a frequency output needs a converter to a voltage. Off until enabled.

FEAT_FLEX · 210 bytes of ROM · 5 bytes of module RAM · RAM: module RAM (5 bytes)

Fuel by gear

Adds or takes away fuel in each gear: the long pull in top gear leaner or richer than the short ones. Needs gear detection. Off until enabled.

FEAT_GEARFUEL · 77 bytes of ROM · 2 bytes of module RAM · RAM: module RAM (2 bytes) · needs Gear detection

Individual cylinder fuel trims

A fuel trim for each cylinder, applied all the time. The skeleton already has the per-cylinder table (stock P13, like the P30, uses it only in closed loop); this takes that condition out, so the trims hold at full throttle too. The trims (CylinderFuelTrim, in the skeleton calibration) default to 0 %, so building it in changes nothing until they are set.

FEAT_CYLTRIM

Injector size and fuel trim

Scales every pulse width for injectors of a different size (the size the calibration was written for against the size fitted) and adds a trim of its own, so a change of injectors or fuel is one setting instead of a new VE map. Off until enabled.

FEAT_FUELTRIM · 154 bytes of ROM · 4 bytes of module RAM · RAM: module RAM (4 bytes)

Maps indexing (alpha-N)

Looks up the fuel and ignition maps on a load worked out from the throttle (alpha-N) instead of from MAP: for individual throttle bodies and big cams, where MAP barely moves. Crossover points pick where it takes over: at or above either the throttle or the MAP point the throttle table is used, below both the MAP sensor as stock. A throttle point of 0 % means always. Off until enabled.

FEAT_ALPHAN · 108 bytes of ROM · RAM: 27Eh (the load used)

Nitrous (N2O)

While the arming switch is on, the throttle is open and the rpm is inside its window, the nitrous maps (a second fuel and ignition map, low and high cam, set up for the base shot - a 50 hp jet, say) are used, and an output can drive the solenoid. A shot input - a voltage on a free analog pin, or a serial input over the datalog cable - scales how far the nitrous maps are from the normal ones: 100 % is the maps as tuned, 150 % half as much more fuel and timing out again (a 75 hp jet), 200 % twice the change (100 hp). The shot table says what each voltage means, blended between its points. Off until enabled.

FEAT_NITROUS · 1,129 bytes of ROM · 6 bytes of module RAM · RAM: 0FDh bit 5 (spraying), module RAM (6 bytes: the shot factor, and the lookup's map, column and first value kept between its two lookups) · cannot be built with Secondary maps (full fuel and ignition maps), Secondary tune on a switch

Secondary maps (full fuel and ignition maps)

A complete second set of fuel and ignition maps, low and high cam (FuelLow2, FuelHigh2, IgnitionLow2, IgnitionHigh2), used instead of the first set while a switch input is on and, if set, above an rpm and a throttle: race fuel and pump fuel, a valet tune, a nitrous or boost map. They start as copies of the first maps. They are the same size as the first maps (twice as large with extended maps): about 820 bytes, 1,640 with FEAT_EXTMAPS. Off until enabled.

FEAT_DUALMAPS · 964 bytes of ROM · RAM: 0FDh bit 0 · cannot be built with Secondary tune on a switch, Nitrous (N2O)

Secondary tune on a switch

A second tune for a switch input: while it is on, fuel and timing change by two tables against rpm - race fuel against pump fuel, a valet tune, or a nitrous map with the timing pulled. Off with the switch off. Off until enabled.

FEAT_MAPSWITCH · 155 bytes of ROM · 5 bytes of module RAM · RAM: module RAM (5 bytes) · cannot be built with Secondary maps (full fuel and ignition maps), Nitrous (N2O)

Idle

Anti-stall

When the rpm drops below a point with the engine running, it does what it can to keep it going: the idle valve opened to a set duty, timing added, and optionally the A/C compressor and the alternator switched off to take their load away. Back to normal above a higher rpm, after a hold time. Off until enabled.

FEAT_ANTISTALL · 236 bytes of ROM · 3 bytes of module RAM · RAM: 0FDh bit 2, module RAM (3 bytes)

Rolling idle

At idle, one injector opening (or one spark) in every few is left out, so a different cylinder misses each time round and the idle rolls and lopes like a big-cam engine. Only below an rpm and a throttle, at a standstill, with the coolant warm and (optionally) a switch on. Skipping an injector is the gentle way; skipping a spark sends that cylinder's fuel into the exhaust. Off until enabled.

FEAT_ROLLIDLE · 349 bytes of ROM · 4 bytes of module RAM · RAM: 0FBh (event count), 0FCh bit 1, 0FDh bits 3-4, module RAM (4 bytes)

Ignition

Timing by gear

Adds or takes away timing in each gear: less in the low gears where the load builds quickly, more in the high ones. Needs gear detection. Off until enabled.

FEAT_GEARIGN · 96 bytes of ROM · 2 bytes of module RAM · RAM: module RAM (2 bytes) · needs Gear detection

TPS tip-in retard

Pulls timing for a moment when the throttle opens quickly, then gives it back a step at a time: the knock-free way through the lean spike of a sudden tip-in. Only below a set rpm. Off until enabled.

FEAT_TPSRETARD · 181 bytes of ROM · 5 bytes of module RAM · RAM: module RAM (5 bytes)

Traction control

Watches how fast the rpm climbs in each gear: faster than the car can accelerate means the tyres have let go, and timing is pulled a step at a time until the climb slows, then given back. Needs gear detection. Off until enabled.

FEAT_TRACTION · 187 bytes of ROM · 4 bytes of module RAM · RAM: module RAM (4 bytes) · needs Gear detection

Limits

Burnout control

A second standing rpm limit on its own input, for a burnout or a water-box warm-up: while the input is on and the car is below a road speed, the revs are held at the burnout rpm. Separate from launch control, so both can be set up on different switches. Off until enabled.

FEAT_BURNOUT · 58 bytes of ROM · RAM: 1C2h-1C5h (shared cut requests), the rev cap: 2 bytes of module RAM shared by every rev limit (lib.asm)

Full throttle shift (flat shift)

Change gear without lifting: with the throttle past a point and the car moving, pressing the shift input (the clutch switch, or any switch input) holds the revs at the shift rpm with an ignition cut, so the turbo stays spooled and the engine does not flare while the clutch is in. Off until enabled.

FEAT_FTS · 82 bytes of ROM · RAM: 1C2h-1C5h (shared cut requests), the rev cap: 2 bytes of module RAM shared by every rev limit (lib.asm)

Ignition cut modifier

Shapes every ignition cut the limiters ask for (rev limit, launch, full throttle shift...): the cut lasts a time (its own for launch and for the shift), then sparks come back for the re-fire time, and again while the limiter holds. While any ignition cut is wanted it can add fuel and hold the timing at one value, for the pops and bangs of a two-step. Re-fire 0 keeps the plain cut. Off until enabled.

FEAT_IGNCUTMOD · 270 bytes of ROM · 2 bytes of module RAM · RAM: module RAM (2 bytes)

Launch control (two-step)

Holds the revs at a launch rpm while the car is standing (below a road speed) and the launch input is on - the clutch switch, or any of the switch inputs - so it leaves the line on boost and in the torque. Past the road speed, or with the input off, the normal limiter is back. Ignition cut (the usual two-step), fuel cut, or both. Off until enabled.

FEAT_LAUNCH · 68 bytes of ROM · RAM: 1C2h-1C5h (shared cut requests), the rev cap: 2 bytes of module RAM shared by every rev limit (lib.asm)

Rev limit by gear

A rev limit of its own for each gear: lower in first and second to keep a car hooked up, the full limit in the tall gears. Fuel cut (or ignition) with a 3 % band. Needs gear detection. Off until enabled.

FEAT_GEARLIMIT · 125 bytes of ROM · RAM: 1C2h-1C5h (shared cut requests) · needs Gear detection

Rev limiter (ignition or fuel cut, per cam)

A limiter of your own on top of the skeleton's: it cuts at one rpm and lets the engine back in at a lower one, separately for the low cam and the high cam (VTEC solenoid on), with fuel cut, ignition cut or both. Ignition cut keeps fuel flowing, the sharper-sounding "pops and bangs" limiter; fuel cut is kinder to the catalyst. Off until enabled.

FEAT_REVLIMIT · 55 bytes of ROM · RAM: 1C2h-1C5h (shared cut requests), the rev cap: 2 bytes of module RAM shared by every rev limit (lib.asm)

Rpm ceilings by road speed

A rev limit that depends on road speed: five speeds, falling, each with the rpm the engine may reach at or above it. For gentle running-in, for keeping a learner under a limit in the low gears, or for a lower limit at a standstill. Fuel cut (or ignition) with a 3 % band. Off until enabled.

FEAT_CEILING · 132 bytes of ROM · RAM: 1C2h-1C5h (shared cut requests)

Speed limiter (always or by switch)

Cuts fuel at a road speed - all the time (a valet or a learner setting), or only while a switch input is on (a pit-lane limiter on a button). Lets it back in 2 km/h under the limit. Off until enabled.

FEAT_SPEEDLIMIT · 106 bytes of ROM · RAM: 1C2h-1C5h (shared cut requests)

Options

Board options override

The ECU decides its equipment variant (automatic, baro sensor, electrical load detector, knock unit, VTEC checks...) from its ID at power-up. This sets any of those flags in software instead: force one on or off whatever the ID says, for a swapped engine or another board. Nothing is forced until a box is ticked.

FEAT_CFGOVERRIDE · 78 bytes of ROM

Watermark

Up to 16 characters of your own (a name, a tune number, a date) stored in the ROM scrambled, so they do not show in a hex view, with a check word worked out from them. The app shows the text and whether it is intact: an edit made any other way than through the app (a hex editor, another tool) shows as modified. It also holds an open password: OkiRomSim asks for it before it opens the ROM (a salted hash is kept, not the password). Neither changes how the ROM runs. 46 bytes.

FEAT_WATERMARK · 47 bytes of ROM

Outputs

A/C load disable

Keeps the A/C compressor clutch off at wide throttle, above an rpm, or below an rpm (at a low idle, where it could stall the engine), and for a hold time after (the clutch held off: output 9, PB.0 on the P13). Off until enabled.

FEAT_ACCUT · 113 bytes of ROM · 1 bytes of module RAM · RAM: module RAM (1 byte)

FEAT_GIO4 · 376 bytes of ROM · 1 bytes of module RAM · RAM: 1C1h bit 7, module RAM (1 byte)

IAB (intake butterflies)

Opens the intake manifold's secondary butterflies (IAB, on B16/B18C manifolds) above an rpm and shuts them again below a lower one, through one of the outputs the skeleton leaves free (the EVAP purge output is the usual one on a car without purge). Off until enabled.

FEAT_IAB · 113 bytes of ROM · RAM: 1C1h bit 0 (its state)

Rpm-switched output

A general-purpose switch: an output comes on above one rpm (and above a throttle opening, if set) and goes off below another - a second shift light, a nitrous arming signal, an intercooler spray, a relay for a fan. Uses one of the outputs the skeleton leaves free. Off until enabled.

FEAT_RPMSWITCH · 134 bytes of ROM · RAM: 1C1h bit 1 (its state)

Smart alternator

Turns the alternator's charging down (the alternator control line, PB.3) under heavy load - wide throttle or high boost above an rpm - for the power it takes, and back to normal once the load has gone for the hold time or if the battery falls below a minimum. Which level of PB.3 turns charging down depends on the alternator and wiring: check it on the car. Off until enabled.

FEAT_SMARTALT · 125 bytes of ROM · 1 bytes of module RAM · RAM: module RAM (1 byte)

Tachometer output

A tachometer signal on one of the free outputs, for an aftermarket tacho or a shift light that wants one: the output changes state at every spark interrupt, two pulses per crank revolution: the signal a 4-cylinder tacho expects from the igniter. Off until enabled.

FEAT_TACH · 164 bytes of ROM · RAM: 1C1h bit 3 (its state)

VTEC control and alternative output

The VTEC page as the established tuning software lays it out: switch VTEC off altogether (a non-VTEC head, or a conversion not wired yet), or engage it on your own points - an engage rpm at high throttle and one at low throttle, a drop-out margin, and minimum coolant, road speed and manifold pressure, each check able to be switched off. Can also repeat the VTEC solenoid on another free output: a VTEC lamp, or a solenoid wired to a different pin. Until "Use these engage points" is ticked the stock VTEC points decide, as without the module.

FEAT_VTECCTL · 290 bytes of ROM

Warning lamp (coolant / battery)

Lights a lamp - the check-engine lamp unless another output is chosen - while the coolant is hotter than a set temperature, or the battery voltage is low with the engine running (a failed alternator). The skeleton has no trouble codes, so this is the one warning left on the dash. Off until enabled.

FEAT_WARNLAMP · 73 bytes of ROM · RAM: 1C1h bit 2 (its state) · cannot be built with Shift light on the check-engine lamp

Protection

Anti-start

The ECU powers up with fuel and spark cut, and stays that way until the secret is given: a switch input on (or off, inverted) with the throttle pressed past a point, before cranking. The A/C switch by default: throttle alone would clash with clearing a flooded engine, and nobody reaches for the A/C to start a car. Any of the switch inputs can be picked instead. Once unlocked it stays unlocked until the ignition is switched off. Off until enabled.

FEAT_ANTISTART · 94 bytes of ROM · RAM: 1C2h-1C6h (shared cut requests, lock flag)

Coolant temperature protection

Once the coolant is hotter than a set temperature the engine is held to a lower rev limit, so an overheating engine limps home instead of being driven hard. Fuel cut, ignition cut or both. And a warm-up limit: a lower rev limit while the coolant is colder than a second temperature, so a cold engine is not driven hard. Each off until enabled.

FEAT_ECTPRO · 196 bytes of ROM · 2 bytes of module RAM · RAM: 1C2h-1C5h (shared cut requests), the rev cap: 2 bytes of module RAM shared by every rev limit (lib.asm)

Lean protection

Watches a wideband O2 controller on an analog input and cuts the engine when it runs lean under load: leaner than a set AFR, with manifold pressure and rpm above set points, for longer than a delay. It stays cut until the pressure falls back, so a lean pull on boost ends at once instead of melting a piston. Off until enabled.

FEAT_LEANPRO · 146 bytes of ROM · 1 bytes of module RAM · RAM: module RAM (1 byte), 1C2h-1C5h (shared cut requests)

Sensor protection (oil / fuel pressure)

Watches a sender on an analog input - an oil pressure or fuel pressure sender, a second wideband - and cuts the engine when its reading is on the wrong side of a level above an rpm for longer than a delay: oil pressure lost at speed ends the pull at once. It stays cut until the reading is back, or the rpm is under the point, so the engine idles home. Off until enabled.

FEAT_SENSORPRO · 131 bytes of ROM · 1 bytes of module RAM · RAM: module RAM (1 byte), 1C2h-1C5h (shared cut requests)

Sensors

Gear detection

Works out the gear from the ratio of rpm to road speed, for everything that depends on the gear: rpm ceilings, fuel and timing by gear, traction control, the gear-based shift light. Set the boundaries between gears for the gearbox and tyres fitted. Gear 0 below a road speed, or with the clutch in (a ratio no gear has).

FEAT_GEAR · 102 bytes of ROM · RAM: 27Fh (the gear)

Road speed correction

Corrects the road speed for a different final drive or tyre size, so the speedometer signal the ECU works from (speed limits, gear detection, launch, the datalog) reads true. 100 % changes nothing.

FEAT_SPEEDCORR · 41 bytes of ROM

TPS sensor end points

Rescales the throttle sensor to the volts it gives closed and wide open, so a sensor that does not read like the stock one still gives 0-100 % to everything that uses the throttle. Off until enabled.
