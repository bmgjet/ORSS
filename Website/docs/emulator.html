Emulators and flashing

Get the ROM into the car: an emulator for changes that land as you make them, or a chip when the tune is done.

A ROM emulator

A Moates Ostrich 2.0 or Demon sits in the ECU's chip socket and serves the ROM from its own memory, which the program can change while the engine runs.

  1. Settings > Emulator & datalog > Emulator: pick its serial port.
  2. In the calibration editor's Emulator menu: Connect / disconnect. The dot beside the menu is green while connected, blinking orange while a lost link is rebuilt.
  3. Upload sends the whole ROM; Validate reads it back and compares.
  4. Tick Upload on changes and every change from then on — a cell, a setting, a patch — goes to the emulator as it is made, only the bytes that changed.

Download reads what the emulator holds into the program (to start from what is in the car).

With the engine runningA change reaches the ECU at once. Make small steps, and keep a known-good ROM to upload back.

Hit trace from a real ECU

An emulator sees every byte the ECU reads. With Hit trace ticked on the Trace tab, those reads are recorded and coloured on the source — which code the car runs and which tables it reads. See Hit trace.

Burning a chip

  1. Tools > Save .bin… writes the 32 KB image, its checksum right.
  2. Program it into a 27C256 / 29C256 with your chip programmer.
  3. For a 64 KB chip (27C512, SST27SF512), use the Bin tool to place it in the upper half, or to put two tunes on one chip.

A ROM built from the skeleton checks its own checksum while it runs: a byte changed by anything that does not keep the checksum right makes the ECU flag it. The program keeps it right on every change and every save.
