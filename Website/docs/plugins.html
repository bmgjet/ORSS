Plugins

Add to the program with a .NET class library: menu entries, buttons, tabs, windows, calibration pages, settings — or a new source for the datalog.

Using a plugin

  1. Put the plugin's .dll in the Plugins folder beside the program (or anywhere).
  2. Settings > Plugins: add it, and tick it on.
  3. What it adds appears — usually under a Plugins menu on the toolbar, which shows only while a plugin is loaded.

ScanTool comes with the program: an ELM327 on a serial port, the standard OBD-II readings mapped onto datalog channels, so the gauges, graph, recording and map trace all work from it.

Only load plugins you trustA plugin runs inside the program with everything it can do.

Writing one

A plugin is a class library referencing RomSimStudio.dll, with one public class implementing IOkiPlugin:

using OkiRomSim.Desktop;

public sealed class HelloPlugin : IOkiPlugin
{
    public string Name => "Hello";
    public string Description => "Says hello, and adds 5 % to the first fuel cell.";
    public string Version => "1.0";

    PluginContext _app = null!;

    public void Start(PluginContext app)          // on the UI thread, once
    {
        _app = app;
        app.AddMenuItem("Say hello", () => app.Log("hello"), "An example.", "👋");
        app.AddSettingsPage("Hello", () => new Avalonia.Controls.TextBlock { Text = "Settings for Hello" });
        app.Sim.ItemWritten += item => app.Log($"{item.Name} written");
    }

    public void Stop() { }                        // stop threads, close ports
}

The PluginContext gives the whole program — the window, the simulator and ROM (Sim: read and write any table, the definitions, the machine), the calibration editor, the datalog page and the settings — and tidy ways in: menu entries, toolbar buttons, tabs, windows, calibration pages, a section at the bottom of a feature page, a settings page, a data folder and settings of its own, and frames fed straight into the datalog page. Writes to the ROM go through the same limits and undo as the editor's.

Driving the emulator. A plugin for an emulator of its own calls app.TakeOverEmulator(...) with a class implementing IEmulatorTakeover (connect, download, upload, validate, real-time update and its link state). While the plugin is enabled the app's Emulator menu, the Datalogging menu's and the datalog page's Connect, and both status dots go to it, and the app's own emulator link lets go; switching the plugin off hands them back. The ALPHAemu plugin works this way.

Settings > Plugins in the program carries the full guide, with an example for every way in, ready to copy.
